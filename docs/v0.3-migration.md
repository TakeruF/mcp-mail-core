# mcp-mail-core v0.3 migration

v0.3 makes package consumption reproducible, rejects capability/method drift at
host construction, adds provider-neutral host composition, and makes draft
cleanup outcomes part of the public adapter contract.

## Package boundary

Consume the exact CI or release artifact instead of rebuilding an unpublished
Core tarball independently in every provider repository. The package exports:

- `mcp-mail-core` for the domain, service, MCP host, Gmail adapter, and contract
  gate;
- `mcp-mail-core/testing` for the framework-neutral provider contract inspector.

Before updating a provider lockfile, install the artifact in a fresh consumer,
import its runtime, compile the adapter as `MailProviderAdapter`, and run the
provider's synthetic integration suite. A missing artifact or contract mismatch
must fail rather than skip.

## Draft result contract

`updateDraft` now returns `DraftReplaceResult`:

```ts
{
  providerDraftId: string;
  providerMessageId: string;
  previousDraftDisposition: "trashed" | "retained" | "provider-managed";
  warning?: string;
}
```

`sendDraft` now returns `DraftSendResult`:

```ts
{
  providerMessageId: string;
  providerThreadId?: string;
  draftDisposition: "trashed" | "retained" | "provider-managed";
  warning?: string;
}
```

Gmail uses `provider-managed`. An IMAP adapter that moves the previous or sent
draft to Trash uses `trashed` only after observing successful cleanup. If the
message was sent but cleanup failed, it must return `retained` and a safe warning
that says the message was sent and must not be resent. It must not throw a plain
send failure after confirmed delivery.

## Provider contract gate

`createMailHost` and `MultiAccountMailService` call `assertProviderContract`
before use. An adapter must keep these pairs consistent:

- `threads` and `getThread`;
- `attachments` and `getAttachment`;
- `drafts` and all of `createDraft`, `updateDraft`, and `sendDraft`;
- send, reply, forward, archive, Trash, and flags with their matching methods.

v0.3 still rejects permanent deletion. Provider packages should also call
`inspectProviderContract` in their own tests so failures identify every mismatch
at once.

## Host composition

Provider packages retain credential and transport ownership and inject configured
adapters into Core:

```ts
const host = createMailHost({
  registry,
  providers: [gmailAdapter, qqAdapter, icloudAdapter],
  cursorSecret,
});

await host.server.connect(transport);
```

No provider may choose a default account for writes. Account metadata must keep
`providerIdentity` separate from the internal `credentialId`, and every adapter
must fail closed when those identities do not match.

## Rollout order

1. Update the adapter result mappings and compile against the exact v0.3 artifact.
2. Run provider mock tests and Core host integration tests.
3. Run the provider's opt-in read-only canary.
4. Run dedicated draft replacement and send fixtures, checking the returned
   cleanup dispositions.
5. Repin the provider only after the standalone rollback path remains verified.
